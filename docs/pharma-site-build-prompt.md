## Role and deliverable

You are building a production website and admin panel for **{{COMPANY_NAME}}** (legal name
**{{LEGAL_NAME}}**), an Indian pharmaceutical **marketing and distribution** company that sells to
the trade (distributors, stockists, chemists, hospitals, institutions) — not to patients. Build the
complete system end to end: public site, product catalogue, enquiry handling, admin panel, data
import pipeline, image pipeline, deployment kit and docs. Do not stop at a landing page. Ask me
nothing you can decide yourself; record every assumption in `docs/decisions.md`.

### Inputs you will receive (look in the project root)
- **Logo** `{{LOGO_FILE}}` — sample the brand palette from it; generate favicon/app icons from its mark.
- **Product spreadsheet** `{{SHEET_FILE}}` — one worksheet: title rows, then section-heading rows
  (one text cell = a segment), then product rows `S.No | Brand (with form suffix e.g. "TAB", "SYP",
  "INJ.", "NASAL DROP") | Composition | Pack`. Serial gaps and blank-brand rows occur.
- **Pack shots** folder `{{PACK_FOLDER}}` — square product carton renders, may carry a contact strip
  baked along the bottom edge. Filenames are brand + form, inconsistently spelled.
- **Visual aids** folder `{{VISUAL_FOLDER}}` (optional) — portrait physician leaflets with
  indications/benefit claims.
- **Design references** (screenshots/URLs) — take the best of each; the first listed is preferred.
- **Company details**: address `{{ADDRESS}}`, phone `{{PHONE}}`, email `{{EMAIL}}`, domain `{{DOMAIN}}`.

## Fixed stack (do not substitute)
- **Next.js 16 App Router**, React 19, TypeScript strict, **Tailwind CSS v4** (CSS-first `@theme`,
  no config file). Read `node_modules/next/dist/docs/` before writing code — v16 differs from older
  versions: `params`/`searchParams` are Promises, global `PageProps<>`/`LayoutProps<>`/`RouteContext<>`
  types, `middleware` is now `proxy`, `next/image` `priority` is deprecated (use
  `loading="eager"` + `fetchPriority`), `images.remotePatterns` must use the object form (a
  `new URL()` pattern rejects query strings).
- **MySQL 8+** via **Drizzle ORM** + `mysql2`; migrations generated by drizzle-kit and applied with
  `drizzle-orm/mysql2/migrator` from a script (no CLI needed at runtime).
- **better-auth** (drizzle adapter, `admin` plugin with roles `admin` and `editor`, `nextCookies`).
- **zod 4** for every input; **sharp** for images; **nodemailer** for SMTP; **marked** for blog
  Markdown with raw HTML escaped and a safe-href allowlist; **lucide-react** icons; `server-only`.
- Pin exact versions; use React/Next releases patched for CVE-2025-55182 ("React2Shell").
- Hosting target: a **Linux VPS** (nginx → PM2 → `next start`), MySQL on the same box, uploads on
  local disk **outside the repo**. Explain in the docs why serverless hosts (Vercel) break admin
  uploads (ephemeral filesystem).

## Compliance rules (Indian pharma — these override design wishes)
The site must be defensible under the Drugs and Magic Remedies (Objectionable Advertisements) Act
and the UCPMP code:
1. **Facts only** for products: brand, dosage form, composition, pack. No efficacy, benefit,
   "relief", "cure", "treat", disease names, or condition+product pairings anywhere in copy.
2. **Trade-only** framing site-wide: every product page and listing carries a note that the
   information is for healthcare professionals and the trade, not medical advice.
3. A **Disclaimer** page, linked from the footer and product notes.
4. A **copy-compliance scanner** `scripts/check-copy.ts` (AST-based over `app/`, `components/`,
   `lib/`, plus `data/catalogue/ranges.json`) run by `prebuild`; it fails the build on claim or
   condition wording. Allow line-level exemptions only via an explicit `// copy-check:` comment.
5. The spreadsheet importer flags rows whose name/composition match claim/condition patterns and
   imports them **unpublished** with a review note, listed in the import summary.
6. Switches, all default **off**, "pending counsel review": `SHOW_MRP_PUBLIC`,
   `SHOW_PRESCRIBING_SPECIALITIES`, `SHOW_VISUAL_AIDS`. Prices and specialities must never be sent
   to the browser when off (use a narrowed type for client payloads). Visual aids stay visible in
   the admin with a "hidden on site" badge.
7. Testimonials publish only when both "permission obtained" and "published" are ticked.
8. Stock photos are never presented as the product: a product with no pack shot shows the segment
   photo only as a banner behind the segment icon, and the product page says "Pack image available
   on request".

## Information architecture
Public pages: Home, About (profile, vision & mission, director message, offset photo panels),
Quality & certifications, Products (filterable catalogue), one page per segment, one page per
product, New additions, Blog index + post, Contact, Disclaimer, 404, `sitemap.xml`, `robots.txt`.

**Home, in order:** hero (headline, intro with live product/segment counts, two CTAs, a photo panel
clipped by a diagonal with two floating stat cards, a "Find a product" search card overlapping the
hero's bottom edge) → auto-scrolling segment marquee → about teaser (photo + three stat tiles) →
segment grid (intro cell + one card per segment with photo header, icon tile, product count and
forms + a "view all" card) → catalogue preview strip (one photographed product per segment,
horizontally scrollable) → audiences band → "Why us" (feature list on an offset tinted panel +
overlapping catalogue card) → testimonials (hidden when none) → latest posts → enquiry band.

**Chrome:** fixed header, transparent over the hero and solid after scroll; the phone number sits
on a translucent pill so it stays legible over any backdrop; dropdowns for About and Products;
full-screen mobile menu. Footer with segments, quick links, contact details, hours, disclaimer
link. Floating WhatsApp button when a WhatsApp number is set. A **call-back dialog** that
auto-opens after ~8 s on the home page only (configurable paths and quiet period).

**Catalogue browser** (`/products`, client component, filters mirrored into the URL, first render
from server-read `searchParams` so HTML already contains results): search across brand, form,
composition, pack and segment (all terms must match); segment list (vertical sticky sidebar on
desktop, swipeable chips on phones); dosage-form select; "new only"; result count; removable
chips; paginate 24 at a time. After any filter change, scroll the results back into view **only if
their top has scrolled out of sight** (respect reduced motion).

**Product card:** pack shot banner (4:3, `object-contain`, `mix-blend-multiply` on a light tint so
the render's white background disappears) with dosage-form pill and "New" badge; segment icon tile
straddling the banner edge; title (stretched link covering the card), segment name, composition
(line-clamped), pack. Phones: compact row with a 64 px thumbnail. Without a pack shot: segment
photo banner from `sm` up, icon tile on phones.

**Product page:** hero with breadcrumbs; gallery (main + thumbnails, blended like the cards) or the
branded icon tile; facts table; enquire + call-back buttons; trade note; related products (same
form first, nearest sort order); segment banner. JSON-LD `Product`. Retired slugs 308-redirect to
their successor from `data/catalogue/renamed-slugs.json`; a product whose segment changed
redirects to its new URL.

## Data model (Drizzle, MySQL)
`ranges` (slug, shortName, sourceHeading, icon, sortOrder, imagePath, imageAlt) · `products`
(slug unique, brand, dosageForm, composition, pack, mrp, mrpNote, prescribingSpecialities, rangeId,
sortOrder, isNew, isPublished, reviewNote, timestamps via `.defaultNow().$onUpdate()`) ·
`product_images` (productId cascade, filePath, alt, width, height, sortOrder) · `enquiries` (kind
enquiry|callback, name, organisation, role, email, phone, city, preferredTime, message, productId
set-null, productLabel, status new|handled, emailStatus + emailError, whatsappStatus +
whatsappError, createdAt) · `site_settings` (key, JSON value — company profile, contact details,
director) · `credentials` · `testimonials` (hasPermission, isPublished) · `blog_posts` (slug,
title, excerpt, Markdown content, cover, author, publishedOn, isPublished) · better-auth tables.
Image paths starting with `/` are served from `public/`; others from the upload folder.

## Catalogue import pipeline
- `scripts/catalogue-parse.ts` (exceljs): detect section headings against
  `data/catalogue/ranges.json` (fail loudly on an unknown heading), skip title rows, warn on serial
  gaps and blank brands. Split brand from form with an ordered suffix table (eye/ear/**nasal**
  drops and nasal sprays before generic drops; dry syrup and `D/S`; `SYP`, `SUSP`, `INJ`, `TAB`,
  `CAP`, softgel, sachet, powder, ointment, gel, soap, lotion, shampoo, wash, cream, gargle, oil,
  `SPF-nn`). Abbreviations are stripped from the display name; whole words ("Eye Drop", "Soap")
  stay. A trailing bracket is unwrapped **only if it holds a form** (`AYURATIN-(LIVER SYRUP)`);
  variants like `(VANILLA)` stay bracketed. Title-case names keeping codes (DSR, SPF, DHA);
  normalise composition units and packs. **Deterministic slugs:** brand → brand+form when the brand
  repeats (without repeating a form already in the name) → brand+pack size when the same product is
  listed per pack size → `-2`.
- `scripts/db-seed.ts`: `--dry-run`, `--replace` (wipe + re-import products and their images),
  `--images-only` (idempotent image sync); starter blog posts inserted only when missing; prints
  per-segment counts and the review list.
- `scripts/create-admin.ts`: masked password prompt, creates an `admin` user.
- `scripts/db.ts`: shared pool plus `describeDbError()` mapping `ER_ACCESS_DENIED_ERROR`,
  `ER_BAD_DB_ERROR`, `ER_DBACCESS_DENIED_ERROR`, `ECONNREFUSED`… to actionable fixes (Drizzle hides
  the driver error behind "Failed query"). Remind users to percent-encode `@` etc. in the password.

## Image pipeline
- Raw client folders stay **gitignored**; `scripts/catalogue-images.ts` converts them with sharp into
  `public/catalogue/{packs,visuals}/<slugified-filename>.webp` (packs ≤1200 px q82, visuals ≤1600 px
  q78; skip unchanged sources; `--force`; remove stale outputs). **Trim the baked-in contact strip**
  on pack shots: the last row must be ≥90 % solid brand-blue; the band ends at the first ≥98 %
  light row above it. (Note: sharp's `.stats()` reads the *input*, not an extracted region — use
  raw pixel buffers.)
- Match files to product slugs: explicit `data/catalogue/image-overrides.json` per folder first
  (value `null` = known product not in the sheet), else unique normalised-brand match. Validate
  every override slug against the parsed sheet and exit non-zero on an invalid one. Write
  `data/catalogue/images.json` (file, kind, source, width, height, factual alt, products[]) and
  print coverage per segment plus unmatched/ambiguous lists.
- Seed attaches images idempotently (packs sort 0…, visuals 100…), refreshes size/alt on rows it
  owns and never touches admin uploads.
- Admin uploads: validate real image via sharp metadata, size limit from `MAX_UPLOAD_MB`, rotate,
  fit 1600, WebP q82, random UUID name, path-traversal-safe resolver, served by a route with
  immutable cache headers.
- Stock photography: **free Unsplash licence only** (Unsplash+ / Getty needs a paid licence — never
  hotlink it). One slot per section/segment in `lib/site/photos.ts` with credit and crop position;
  any slot is overridden by dropping `public/photos/<slot>.(jpg|png|webp)`. Prefer high-resolution
  sources whose subject fills the frame; a portrait photo suits the tall diagonal hero panel.

## Enquiries and notifications
Server actions with zod validation, honeypot and per-IP rate limit; the enquiry is **always saved
first**, then email (SMTP) and WhatsApp run concurrently and never block or fail the user response;
each outcome is stored (`pending|sent|failed|not-configured`) and shown as badges in the admin.
WhatsApp providers by `WHATSAPP_PROVIDER`: `meta` (Cloud API **template** message — business-
initiated messages require an approved Utility template; document its exact body with five
parameters: kind, name, phone, organisation+city, product/message) or `twilio` (content template, or
free text in the sandbox). Sanitise template parameters (no newlines, no 4+ spaces), 10 s timeouts,
never log payloads (PII). `npm run whatsapp:test` sends a sample.

## Admin panel (`/admin`, neutral working theme, sidebar + mobile drawer)
Login · dashboard (counts, new enquiries, products missing images, items awaiting review) ·
products (list with filters, create/edit, publish toggle, review note, image manager: multi-upload
with progress, set main, edit alt, delete, visual-aid badge) · segments (reorder, master image
upload/replace/remove, true product counts via join + group by — **not** correlated subqueries,
which Drizzle renders with unqualified columns) · enquiries & call-backs (filter, mark handled,
email/WhatsApp status with error on hover) · company details (profile, vision, mission, director,
contact; blank fields fall back to defaults) · credentials · testimonials · blog (Markdown editor,
preview, publish) · staff (admin-only: create/disable users, roles). Every mutation goes through a
`guarded(role, fn)` wrapper (auth check, `unstable_rethrow`, duplicate-key messages) and ends with
`revalidatePath("/", "layout")`. React 19 forms via `useActionState`; submit with
`startTransition(() => formAction(fd))` so fields don't reset on error.

## Design system
Tokens sampled from the logo in `@theme` (navy, brand blue, sky, green, leaf, surface, line, muted;
card/lift shadows; card radius); display font Plus Jakarta Sans + body Inter via `next/font`.
Buttons `.btn` variants, full-width stacked on phones. Hexagon pattern overlay and dot grids as
texture (as separate `pointer-events-none` layers — never combined with a gradient on the same
`background-image`). Scroll reveal via `data-reveal` → `data-shown` attributes (a class toggle gets
wiped by React on re-render), content visible without JS, disabled for reduced motion. Scrollbar
styling with **standard `scrollbar-color`/`scrollbar-width` only** (any `::-webkit-scrollbar` rule
forces Chrome's legacy scrollbar with a painted track and arrows). Disable native drag ghosts for
`a, img` (CSS `-webkit-user-drag` + a `dragstart` guard for Firefox). Favicon/app icons from the
logo mark with transparent backgrounds (apple-touch icon on brand navy). `suppressHydrationWarning`
on `<html>`, `<body>` and hidden wrappers that extensions (Bitdefender, ColorZilla) stamp.

**Responsive is a hard requirement:** check 320, 360, 390, 768, 1024, 1280, 1440, 1920 px — no
horizontal overflow (`fieldset` needs `min-w-0`; long unbreakable compositions need
`overflow-wrap: anywhere`), 44 px touch targets, every padded card padded at every breakpoint,
offset panels that only work on desktop become full-width bands below `lg`. Verify with real
screenshots (headless Chrome enforces a ~500 px minimum window, so render phone widths inside an
exact-width iframe).

## Deployment kit

the upload limit, optional `if ($http_next_action = "x") { return 403; }` to drop scanner probes),
`deploy/ecosystem.config.cjs` (PM2), `deploy/deploy.sh` (resolves its own directory; pull → `npm ci`

catalogue re-import must run **before** `next build`, because the build prerenders from the DB.

## Quality gates (run before every commit)
`tsc --noEmit`, `eslint`, `npm run check:copy`, `next build`; responsive screenshots of every page
type; dry-run the importer after any sheet change and diff added/removed/renamed products;

re-encoding sources.
